================================================================================
IMPLEMENTATION PRINCIPLES
================================================================================

The objective is to improve responsiveness and conversational quality WITHOUT
rewriting the existing architecture.

The implementation must follow these principles:

• Preserve existing engineering functionality.
• Reuse existing planners, specialists, and memory systems whenever possible.
• Add routing and orchestration instead of replacing proven components.
• Favor composition over duplication.
• Every new component must be modular and independently testable.
• Maintain backwards compatibility with existing engineering workflows.
• Existing APIs should remain unchanged unless absolutely necessary.
• Performance improvements must not reduce engineering accuracy.

================================================================================
PERFORMANCE TARGETS (LATENCY BUDGETS)
================================================================================

The following are maximum acceptable latency targets.

Voice endpoint detection
≤150 ms after user stops speaking.

Intent classification
≤50 ms.

Conversation memory lookup
≤50 ms.

Project cache lookup
≤75 ms.

First streamed LLM token
≤500 ms.

Speech synthesis start
Immediately after first streamed token.

Engineering planning
Runs asynchronously whenever possible.

Repository analysis
Must never delay conversational responses.

Background work
Runs continuously without blocking foreground interaction.

================================================================================
CONVERSATION STATE MACHINE
================================================================================

Every interaction follows a predictable lifecycle.

Listening

↓

Speech Recognition

↓

Intent Classification

↓

Conversation Memory Lookup

↓

Responding (Streaming)

↓

Background Processing (Optional)

↓

Idle

Rules

Conversation must never wait for Background Processing.

Background tasks continue independently.

Interruptions immediately return to Listening state.

Streaming responses begin before background tasks complete.

================================================================================
CACHE INVALIDATION RULES
================================================================================

Project Awareness Cache should refresh ONLY when:

• Git commit changes.
• Files are added.
• Files are removed.
• Files are modified.
• Active branch changes.
• User explicitly requests refresh.
• MARK starts for the first time.

Otherwise

Reuse cached project awareness.

Never perform full repository analysis for ordinary conversation.

================================================================================
EXECUTIVE DECISION LAYER
================================================================================

Before executing any request, MARK performs an Executive Decision Pass.

Question 1

Can this be answered immediately using conversation memory?

YES

Respond immediately.

NO

Continue.

----------------------------------------

Question 2

Does this require project knowledge?

YES

Consult Project Awareness Cache.

NO

Continue.

----------------------------------------

Question 3

Does this require engineering specialists?

YES

Activate Planner.

Delegate required specialists.

NO

Do not activate engineering organization.

----------------------------------------

Question 4

Can any remaining work continue in the background?

YES

Launch asynchronous background tasks.

Continue conversation immediately.

NO

Complete work synchronously.

This decision layer exists to minimize unnecessary computation while preserving
engineering capabilities.

================================================================================
DESIGN PHILOSOPHY
================================================================================

MARK is not a chatbot.

MARK is a persistent executive intelligence.

Conversation should feel immediate.

Engineering should feel deliberate.

Background thinking should be continuous.

Repository awareness should be incremental.

Memory should persist.

Delegation should be intentional.

Every millisecond saved during conversation increases the feeling of
intelligence without reducing capability.

The system should optimize for:

1. Responsiveness
2. Continuity
3. Accuracy
4. Efficiency
5. Executive-level decision making

Every architectural decision should support these five principles.
