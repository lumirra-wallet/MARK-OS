================================================================================
MARK PERFORMANCE & CONVERSATION REDESIGN
Master Engineering Specification
Version: 1.0
Priority: CRITICAL
================================================================================

OBJECTIVE

MARK should no longer feel like a chatbot.

MARK should feel like a persistent executive director that:

• responds almost instantly
• remembers ongoing conversations
• remembers previous project discussions
• never repeats itself unnecessarily
• only performs expensive engineering work when required
• continuously improves itself in the background

The redesign must preserve every existing engineering capability while making
conversation significantly faster and more natural.

================================================================================
PRIMARY GOALS
================================================================================

1. Reduce voice response latency.

2. Make conversation feel human.

3. Prevent unnecessary planning.

4. Prevent unnecessary repository analysis.

5. Separate conversation from engineering execution.

6. Build continuous background intelligence.

7. Stream responses immediately.

================================================================================
PROBLEM ANALYSIS
================================================================================

Current issues observed:

• Every message appears to activate engineering planning.

• Repository analysis repeats constantly.

• MARK repeatedly says:

    "While you were away..."

    "No tests for hi.py..."

even after already reporting them.

• MARK repeatedly introduces itself.

• Small talk triggers the same heavy pipeline used for engineering.

• Voice waits for planning before speaking.

• Conversation feels robotic.
